# Phase 14 — UI Design Contract

> Visual and interaction contract for the Team Deathmatch UI surfaces. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **NOT a web/React app.** This is a **Phaser 3 + TypeScript** game rendered on a fixed **480×320 pixel-art canvas (FIT scale, roundPixels)**. There is NO HTML / CSS / Tailwind / component library / rem / theme system. "Typography" = the `press_start_2p` BitmapText atlas at px sizes on the 480×320 design grid. "Color" = Phaser tint hex values. "Spacing" = pixel coordinates anchored with `setScrollFactor(0)` + `setOrigin` + `setDepth`. "Components" = Phaser GameObjects. Treat every web-oriented field below as adapted to this medium.
>
> All design decisions D-01..D-20 in `14-CONTEXT.md` are LOCKED. This spec formalizes the VISUAL contract for the four surfaces those decisions imply. Where CONTEXT grants Claude's discretion (tween values, exact coords, MVP tie-break), defaults are given and marked **(tunable)** — every tunable value follows the project `*_TUNING` + debug-panel + COPY VALUES loop.

## Spacing Scale

Pixel coordinates on the 480×320 canvas. The project uses an **8px grid** with a 4px half-step (existing HUD: mana bar at x=8/y=14, heart rows 8px apart, cooldown HUD y-step). Declared steps:

| Token | Value | Usage |
|-------|-------|-------|
| half | 4px | Tight inset / sub-glyph nudges |
| base | 8px | Default gap between HUD elements; heart-row pitch |
| 2x | 16px | Score-plate group inset; results table row pitch |
| 3x | 24px | Results section padding (title → table) |
| 4x | 32px | Major vertical break (banner offset, results title block) |

Exceptions:
- **Score plate** is anchored to **canvas center-X = 240**, **y ≈ 8–12** (top edge, **(tunable)**). Must clear the existing mana bar (x=8, y=14, w=60) and hearts (start x=157, y=25/33) — top-center column 100–380 px is free of the left-anchored mana/cooldown HUD and the right-shifted hearts block.
- **Cinematic / results overlays** are centered (`origin 0.5`) on the 480×320 viewport, `setScrollFactor(0)`.

## Typography

All text is `press_start_2p` BitmapText. **BitmapText has no font-weight axis** (single pre-rendered face) — hierarchy is expressed via **size + tint + scale**, not weight. Sizes are px at the 480×320 design resolution. Existing anchors: countdown overlay = 32px, death countdown = 32px, menu items = 16px, lobby title = 16px, HUD micro-labels = 6–8px.

| Role | Size | Treatment | Used by |
|------|------|-----------|---------|
| Display | 32px | center origin, tint per context, `setDepth ≥ 1000` | Map-name banner (surface 1), countdown digit (surface 1), results "winner" line (surface 4) |
| Heading | 16px | center origin | Score-plate numbers (surface 2), results column headers / "MVP" / button label (surface 4) |
| Body | 8px | left or center origin | Results per-player rows (surface 4) |
| Micro | 6px | center origin, dim tint | Optional radial-menu affordance hint "Q/E ELEMENT" (surface 1 reveal), mirrors existing 6px `SHIFT WIND DASH` hint |

Line/letter spacing: default (0). For multi-row results table use **explicit per-row Y placement** (8px BitmapText, row pitch 16px) — do NOT rely on multi-line `\n` alignment for the table (per-row tinting requires separate objects anyway, see surface 4).

## Color

Pixel-art tint palette. The "60/30/10" model maps to: dominant = world/dark overlay, secondary = panel/scrim fills, accent = the two **team colors** + the existing UI gold. Team colors are the load-bearing accent and are reused verbatim from the lobby.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (world / dark) | `0x222233` @ 0.55 alpha (death overlay), `0x000000` (results scrim, alpha (tunable) ~0.7) | Full-screen scrims behind cinematic countdown, death countdown, results screen |
| Secondary (panel) | `0x0a0f1f` @ ~0.9 + `0x2a3a55` 1px stroke (lobby box pattern) | Optional results-screen panel frame; banner backing if used |
| Accent — Team A | `0x44aaff` (cyan-blue) | Team A score number (surface 2), Team A "[A]" bracket, Team A winner text, Team A player rows + MVP (surface 4) |
| Accent — Team B | `0xff5533` (red-orange) | Team B score number (surface 2), Team B "[B]" bracket, Team B winner text, Team B player rows + MVP (surface 4) |
| Accent — UI gold | `0xffdd55` | Countdown digit tint (existing), MVP highlight ring/underline, neutral separators ("–" dash in score, table headers), selected/hover button tint |
| Neutral text | `0xffffff` | Default BitmapText (score dash, table body, button idle) |
| Dim text | `0xcccccc` / `0x888888` | Secondary labels, disabled/idle hints |

**Team color source of truth:** `src/scenes/lobby-scene.ts` — the player-row team **badge tint** constants: `player.team === 0 → 0x44aaff` (Team A), `player.team === 1 → 0xff5533` (Team B). (Note: the lobby *toggle-button fills* use a different pair `0x0066dd` / `0xcc2200` — do NOT use those for text; use the **badge tints** `0x44aaff` / `0xff5533` for all TDM text tinting so the score plate matches the lobby badge a player saw.) Planner should hoist these two into a shared `TEAM_COLORS = [0x44aaff, 0xff5533]` constant (indexable by `PlayerInfo.team`) so lobby, score plate, and results all read from one place.

Accent reserved for: team-score numbers, team brackets, team-colored winner/MVP/rows, the countdown digit, and the MVP highlight + button select state. Never tint body table data or the score dash with a team color (those stay white/gold).

Destructive: not applicable — no destructive form actions in this phase. ("Return to lobby" is non-destructive navigation.)

## Surface 1 — Intro Cinematic (D-18 / D-19 / D-20)

**Extend, do not rewrite.** Builds on the existing `#enterCountdownMode` / `#onCountdownTick` / `camera.zoomTo` / `#combatLocked` machinery (game-scene.ts ~L3604–3683). Players stay locked at spawn the whole sequence via existing `#combatLocked` + movement lock; unlock is still gated by the host-authoritative `COUNTDOWN → ACTIVE` broadcast (D-18 step 7).

### Locked ordering + what is visible at each step

| Step | What happens | Visible | Hidden |
|------|-------------|---------|--------|
| 1 | Map-name banner reveals (typewriter/fade) | Banner only | HP, mana, radial hint, countdown digit |
| 2 | Camera at **map center**, **zoomed OUT** (wider than play zoom). Characters already at spawnpoints | Banner, world (wide) | game HUD |
| 3 | Camera **smoothly pans** map-center → local player | Banner (fading out near end), world panning | game HUD |
| 4 | Camera **zooms IN** to play zoom (today's 1.0) | World at play zoom | game HUD |
| 5 | **UI reveal** — radial-menu affordance + mana bar + HP fade/slide in together | game HUD appearing | banner (gone) |
| 6 | Countdown `5 → 4 → 3 → 2 → 1` (one digit/sec, server-driven) | Countdown digit + HUD | banner |
| 7 | At `0`: movement + casting unlock simultaneously; digit cleared | World + HUD, no overlay | overlay |

### Banner (surface-1 element)
- `press_start_2p`, **32px (Display)**, `setOrigin(0.5)`, `setScrollFactor(0)`, `setDepth ≥ 1000`, tint `0xffffff` (or gold `0xffdd55` to match the countdown — **(tunable)**). Position: horizontally centered, upper third (y ≈ 80–100, **(tunable)** — must not overlap the centered countdown digit at y=160).
- **Reveal animation:** typewriter or fade-in. **Default = typewriter** via incremental `setText` of substrings, OR a `tweens.addCounter` from 0→length driving visible chars.
- **D-19 BUG FIX (the whole point):** the banner "cuts the last letters" because the reveal animation is too SHORT to finish before teardown — **NOT** a width/origin/mask clip. **Fix = scale the reveal DURATION to the map name's character count** so long names always complete: e.g. `revealMs = BANNER_MS_PER_CHAR * name.length`, clamped to `[BANNER_MIN_MS, BANNER_MAX_MS]`. Defaults `BANNER_MS_PER_CHAR ≈ 70`, `BANNER_MIN_MS ≈ 600`, `BANNER_MAX_MS ≈ 2000` **(all tunable)**. Banner teardown (fade-out) must begin **only after** the reveal `onComplete`. **Do NOT widen any container or change origin/mask.**

### Camera (surface-1 motion)
- Reuse `cameras.main.setZoom(outZoom)` + `cameras.main.zoomTo(playZoom, …)` (existing pattern). Add a `cameras.main.pan(player.x, player.y, panMs, ease)` between the wide hold and the zoom-in. Sequence the pan → zoom either via the `pan` completion callback or `tweens.chain`.
- Feel **(all tunable, ranges given — D-20 grants exact values to discretion):**
  - `outZoom` ≈ 0.5–0.65 (existing countdown used 0.6 as the snap-out start — reuse as the wide establishing value).
  - `playZoom` = today's play zoom (1.0).
  - Center hold ≈ 300–600 ms before pan starts.
  - Pan map-center → player ≈ 900–1400 ms, `Sine.easeInOut`.
  - Zoom-in ≈ 700–1100 ms, `Cubic.easeOut`.
- **Late-joiner safety (keep existing rule):** the zoomed-OUT value is set only inside the cinematic, never in `#setupCamera` — a client that misses COUNTDOWN must default to play zoom.

### UI reveal (surface-1 element, step 5)
- HP hearts, mana bar, and a radial-menu affordance fade/slide in **together** after the zoom-in completes, and are **hidden during steps 1–4**. Implement as alpha 0→1 (and optional small Y-slide, e.g. `y: '+=6' → '+=0'`) tween, ≈ 200–350 ms, `Quad.easeOut` **(tunable)**.
- Coordinate across scenes: `GameScene` drives the cinematic; the HUD lives in `UiScene`. Bridge the reveal via `EVENT_BUS` (new `CUSTOM_EVENT`, e.g. `HUD_REVEAL`) so `UiScene` fades its `#hudContainer` in. The score plate (surface 2) reveals in this same beat.
- **Radial-menu affordance:** a 6px micro hint (e.g. `Q/E SWITCH ELEMENT`) near the element gem, mirroring the existing 6px `SHIFT WIND DASH` hint at (240, 308). Reveal with the HUD. Exact copy/position **(tunable)**.

### Countdown digit (surface-1 element, step 6)
- Reuse the existing centered `#countdownText` (32px, `setScrollFactor(0)`, depth 1000, tint `0xffdd55`) and the existing per-tick **pop** tween — keep it exactly: `scale { from: 1.3, to: 1.0 }, duration: 250, ease: 'Back.easeOut'`. Only the label sequence changes (`5..1` instead of `3 2 1 FIGHT`), driven by server ticks (no client `setInterval`).

## Surface 2 — Team-Score HUD Plate (D-15 / D-16 / D-17)

- **Home:** `UiScene`, added to `#hudContainer` (so it reveals/hides with the rest of the HUD during the cinematic).
- **Layout:** **top-center**, anchored to canvas center-X = **240**, **y ≈ 8–12** **(tunable, debug-tunable afterward)**. Must NOT collide with the left-anchored mana bar (x=8,y=14) / cooldown HUD or the hearts block (x 157–237, y 25/33). The top-center band (x 100–380, y 4–20) is clear.
- **Readout:** `[A] 12 – 8 [B]` (D-16). Built from **separate BitmapText objects** so each piece can carry its own tint:
  - `[A]` bracket + Team A number → tint **Team A `0x44aaff`**
  - `–` separator → white/gold, no team tint
  - Team B number + `[B]` bracket → tint **Team B `0xff5533`**
  - All `press_start_2p`, **16px (Heading)**, baseline-aligned, laid out left→right around center-X with ~4–8px gaps, the whole group centered as one unit. (Alternative: one BitmapText + `setCharacterTint` ranges — WebGL only; separate objects are safer and match the per-tint need.)
- **Live update (D-17):** on every score broadcast, `setText` the changed number, then play the **same pop tween shape as the countdown tick** on the changed number object: `scale { from: 1.3, to: 1.0 }, duration: 250, ease: 'Back.easeOut'`. Only the number that changed pops (the other team's number stays still). Re-center the group if digit count grows (e.g. 9→10).
- **Depth:** above world, at HUD depth (inside `#hudContainer`). `setScrollFactor(0)`.

## Surface 3 — Respawn Invulnerability Cue (D-12 / D-13)

- **Visual = reuse the existing post-hit i-frame blink** (alpha pulse) — near-zero new art (D-13). The protected respawned player's sprite pulses alpha while invuln is active.
- **Blink contract:**
  - **Pulse:** alpha tween `1.0 ↔ ~0.35`, `yoyo: true`, `repeat: -1`, `duration ≈ 150 ms` per half (steady, readable flicker). Store the tween ref; **stop it the instant invuln ends** and hard-reset `alpha = 1.0`.
  - **Reads as "protected" vs the hurt-blink:** the post-hit hurt blink is **brief and one-shot** (tied to `invulnerableAfterHitAnimationDuration`); the respawn-protection blink is a **sustained, slower, looping** pulse lasting up to the invuln window (~2–3s). The difference in *duration + rhythm* is the read — same alpha mechanic, longer/steadier loop. (Optional **(tunable)** extra read: a faint team-tint shimmer, but default is alpha-only to honor "near-zero new art".)
  - **When it stops (D-12):** invuln ends — and the blink stops — on the **first of**: local player **movement**, local player **cast**, OR a **max duration ~2–3s** (`RESPAWN_INVULN_MAX_MS`, default 2500, **(tunable)**, server-authoritative per D-14). On stop: kill the pulse tween, set `alpha = 1.0`.
- **Server authority (D-14):** the host tracks invuln-until per player and rejects `spell:hit` on invuln targets; the client also gates locally for immediate visual correctness. The blink is a **pure cosmetic** mirror of the server invuln state — start it when the respawn applies, stop it when the client-side invuln window closes (move/cast/timeout), trusting the server as source of truth.
- **Layering:** the blink overlays the existing local-death flow — it begins right after `#onRespawn` restores position/HP/tint (the death overlay + `RESPAWNING IN N…` countdown is already torn down by `#clearLocalDeath` at that point). Do not blink while the death overlay is up.
- **Depth:** none new — the pulse is on the Player sprite itself, not an overlay.

## Surface 4 — Minimal Results Screen (D-06 / D-07 / D-08)

- **Home:** its own scene/overlay launched on match `ENDED` (D-08), reading per-player stats from the win payload (kills/deaths per player + winningTeam + mvpPlayerId, shape is planner's call per CONTEXT discretion). Read `skills/scenes/SKILL.md` for launch/shutdown lifecycle. Launch over a frozen `GameScene` or as a standalone scene — planner's call; if overlay, dim the world with a scrim.
- **No charts, no damage column, no elaborate animation** (D-06). Minimal is the requirement.

### Layout (480 × 320, all centered on center-X = 240, **(tunable)**)

```
                    [ dark scrim 0x000000 @ ~0.7 over full 480x320 ]
   y≈48    ┌───────────────────────────────────────────┐
           │              TEAM A WINS                    │  32px Display, tinted winner-team color
   y≈96    │   PLAYER          K     D                    │  8px header row, dim/white
   y≈116   │ ★ MVP  Alice      9     3                    │  8px body, row tinted by player's team; MVP gold ★ + gold underline/ring
   y≈132   │       Bob         5     6                    │  8px body, team-tinted
   y≈148   │       Carol       2     4                    │  8px body, team-tinted
            ...
   y≈276   │            [ RETURN TO LOBBY ]               │  16px Heading button
           └───────────────────────────────────────────┘
```

- **Winner line:** 32px Display, tinted with the winning team color (`0x44aaff` / `0xff5533`); `DRAW` in gold `0xffdd55` if `winningTeam == null`.
- **Table:** header row (`PLAYER  K  D`, 8px, dim/white) then one 8px BitmapText **row per player**, **row pitch 16px**. Each player's name+stats tinted with **that player's team color** so teams read at a glance. Sort rows by team then by kills, or kills-desc — **(tunable)**.
- **MVP highlight (D-06):** the highest-kills player. Treatment = a gold `★` prefix + `MVP` tag + a thin gold underline/frame rect (`0xffdd55`) behind/under that row. **Tie-break (CONTEXT discretion):** highest kills; ties broken by **fewest deaths**, then by **first player to reach that kill count** (server-tracked order), then arbitrary stable order. Document the chosen rule in code.
- **Return-to-lobby button (D-06):** match the **established menu button pattern** (main-menu-scene `#buildMenu`, lobby-scene). Pattern = a `press_start_2p` **16px BitmapText**, `setOrigin(0.5)`, `setInteractive({ useHandCursor: true })`, with:
  - idle tint white/dim (`0xffffff` / menu idle),
  - `pointerover`: scale-up tween `scaleX/Y: 1 → 1.05, duration: 100, ease: 'Quad.Out'` + select tint (gold `0xffdd55`),
  - `pointerout`: revert tint + scale `→ 1`,
  - `pointerup`: wire back to the lobby flow (return to `LobbyScene` / rematch).
  - (Optional framing rect behind the label using the lobby box style `0x0a0f1f`@0.9 + `0x2a3a55` stroke if a clearer hit target is wanted — **(tunable)**; the bare-BitmapText hover pattern is the established minimum.)
- **Animation:** minimal only — a single overlay fade-in (alpha 0→1, ≈200ms) is acceptable; no staggered row reveals, no chart growth.
- **Depth:** scene-level (own scene) or `setDepth` above GameScene if overlay; `setScrollFactor(0)` for all elements.
