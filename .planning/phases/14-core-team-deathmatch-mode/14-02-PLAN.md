<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → server (spawn position) | A client must never choose or assert its own spawn position. |
| client `spell:hit` → server (invuln target) | A client could claim a hit on a just-respawned, protected enemy. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-06 | Spoofing / Tampering | spawn assignment | mitigate | Spawn is computed server-side via `room.pickSpawn(playerId, mapId)` from the server-side `SPAWNPOINTS` literal + server-cached living-enemy positions (`#lastPos`/`#hp`). The client receives a `RespawnPayload` and renders it; it never sends a spawn. The naive client-independent offset is removed. |
| T-14-07 | Tampering | hit on invulnerable target | mitigate | `validateHit` rejects any `spell:hit` where `now < #invulnUntil.get(targetId)` (D-14).
