<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client `spell:hit` claim → server | Untrusted: a client claims its spell hit a target for `damage`. Crosses into the authoritative scoring path. |
| client → server (team identity) | A client could attempt to assert its own team or score. Server must never read team/score from the client. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-01 | Tampering / Elevation | server.ts `result.eliminated` scoring branch | mitigate | Kill attribution reads the caster's team ONLY from server-side `#playerInfo` via `addTeamKill(casterId)` / `getTeam(casterId)`; the client never sends team or score. `casterId` is taken from the already-validated `spell:hit` claim that passed `validateHit` (range + freshness + FF). |
| T-14-02 | Spoofing | team-score broadcast | mitigate | `#teamScores` is server-only state; `match:team-score` / `match:ended` are server-emitted broadcasts. Clients render from them and cannot write them. |
| T-14-03 | Tampering | friendly-fire / self-kill scoring | mitigate | `addTeamKill` is guarded by `!room.isSameTeam(casterId, targetId)` AND `validateHit` already short-circuits FF (D-05); a team is never credited for losing its own member. |
| T-14-04 | Repudiation / Integrity | win-check + ENDED transition | mitigate | Win-check (`scores[x] >= TDM_WIN_TARGET`) and `transitionTo('ENDED')` run server-side only; the single `match:ended` broadcast is the sole authority for match end. No client can declare a win. |
| T-14-05 | Denial of Service | flood of forged `spell:hit` to inflate score | accept | Each hit still passes the existing Phase 9.3 `validateHit` (range/freshness) + per-spellId dedupe (`tryConsumeHit`); forging valid-looking hits at scale on a LAN match is low-value/low-likelihood for this phase. Noted, not mitigated further. |
</threat_model>
