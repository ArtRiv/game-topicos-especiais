# Phase 9 — UI Design Contract

> Visual and interaction contract for the LobbyScene waiting room: format selector, map picker, capacity header, and lobby browser row. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Phaser 3 game — no component library; not a React/Next/Vite shadcn target) |
| Preset | not applicable |
| Component library | Phaser 3.87 GameObjects + `add.dom()` for native form controls |
| Icon library | none (text labels + colored rectangles only — matches existing pixel-art aesthetic) |
| Font | `"Press Start 2P"` (existing FONT constants in `src/scenes/lobby-scene.ts:7-10`) |

**Existing palette (do not redefine — extend):**
- `FONT` 10px white — body
- `FONT_TITLE` 14px `#ffdd55` (gold) — scene title only
- `FONT_SMALL` 8px `#cccccc` — labels/hints
- `FONT_SMALL_WHITE` 8px `#ffffff` — list row text/button labels
- `BTN_COLOR` `0x3355aa` / `BTN_HOVER` `0x4477cc` / `BTN_DISABLED` `0x223366`
- `#createButton` helper at line 296 — reuse for the map preview-card click target

## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline padding inside DOM `<select>` / preview-card label gutter |
| sm | 8px | Gap between map preview cards and their label, dot-to-text gap in player row |
| md | 16px | Vertical gap between waiting-room header line and host controls block |
| lg | 24px | Vertical gap between host-controls block and player list |
| xl | 32px | Vertical gap between player list and START button |
| 2xl | 48px | Reserved for future panel-level separators (not used in this phase) |
| 3xl | 64px | Not used in this phase |

**Row spacing precedent:** Existing player list uses 36px row pitch (line 248). Keep this — do not re-spec. Phase 9 controls sit ABOVE the player list, not inside it.

**Exceptions:**
- Map preview card itself: 96px × 64px (3:2 thumbnail at native pixel-art scale) — outside the 4-multiple rule by design (matches Phaser texture pixel scale).
- DOM `<select>` height: ~22px native (browser default) — exempt from token scale; padding inside is 4px (xs).

## Typography

Three roles, two weights (regular only — `"Press Start 2P"` ships single weight; all variation via size + color).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 10px | 400 | 1.5 (15px) — `FONT` |
| Label | 8px | 400 | 1.5 (12px) — `FONT_SMALL` / `FONT_SMALL_WHITE` |
| Heading | 14px | 400 | 1.2 (17px) — `FONT_TITLE` (gold #ffdd55, scene title only) |
| Display | n/a | — | — (no display tier; the pixel font caps at 14px for readability) |

**Phase 9 additions:**
- Capacity header line (`Players 3/6 — 3v3 on Open Field`) → Body 10px white, centered, line height 1.5.
- Format/Map read-only labels (non-host) → Label 8px `#cccccc`, left-aligned beside the host-controls anchor.
- Map preview card displayName → Label 8px `#ffffff` centered below thumbnail.
- Lobby browser row text (`<Host>'s lobby — 3v3 • Open Field • 3/6`) → Label 8px `#ffffff` (extend existing `FONT_SMALL_WHITE` row).

**Forbidden:** No new font families. No bold weight (font has none). No font sizes outside {8, 10, 14}.

## Color

60/30/10 split, mapped to the existing palette. No new hex values for surfaces.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#000000` (Phaser scene clear color) | Scene background |
| Secondary (30%) | `0x223366` / `0x111111` | Lobby/player-row backgrounds, DOM input fill (#111) |
| Accent (10%) | `0x3355aa` (BTN_COLOR) + `#ffdd55` (gold title) | Interactive buttons, scene title only |
| Destructive | `#ff4444` / `0xcc2200` | Disconnect status text; reject/error copy |

**Accent reserved for:**
1. The `START GAME` button (existing primary CTA)
2. The format `<select>` dropdown control (host-only)
3. The selected map preview card border highlight
4. The scene title `WAITING ROOM` (gold `#ffdd55`)
5. Lobby browser row hover state (`BTN_HOVER` `0x4477cc`)

**Accent NOT used for:** capacity header line, read-only labels, player row text, map card thumbnails, non-selected map card borders.

**Team colors (existing, not part of 60/30/10):** `0x0066dd` (Team A), `0xcc2200` (Team B), `0xaaaaaa` (no team). Phase 9 does not touch team colors.

**Phase 9 additions:**
- Selected map card border: `0xffdd55` (gold, accent reuse) — 2px stroke.
- Non-selected map card border: `0x444444` (neutral grey, secondary surface).
- Map card background (both states): `0x111111` (matches DOM input fill).
- Reject error copy color: `#ff4444` (destructive, already used for disconnect message at line 79).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `START GAME` (existing — unchanged by Phase 9) |
| Format selector label (host) | `Format:` followed by the `<select>` |
| Format read-only label (non-host) | `Format: 3v3` (format value injected) |
| Map picker label (host) | `Map:` above the preview cards |
| Map read-only label (non-host) | `Map: Open Field` (displayName injected) |
| Capacity header (everyone) | `Players 3/6 — 3v3 on Open Field` (live values; em dash, lowercase " on ") |
| Map preview card alt label | The `displayName` from `MAP_POOL` (`Open Field`, `Dungeon`) |
| Lobby browser row | `<Host>'s lobby — 3v3 • Open Field • 3/6` (em dash separates host from config; bullet `•` separates config fields) |
| Empty lobby list state | `No open lobbies` (existing — unchanged) |
| Empty map pool state | not reachable (MAP_POOL is hardcoded with ≥1 entry; if `MAP_POOL.length === 1`, render the single card non-interactive — no special copy) |
| Format-rejection error | `Reduce players first (8 > 4 cap)` (numbers injected: `<currentCount> > <newCap> cap`) |
| Generic config-reject error | `Only the host can change lobby settings` (server-side guard; should not surface in UI for non-host since controls are read-only, but copy exists for socket-error fallback) |
| Destructive confirmation | not applicable — Phase 9 has no destructive actions (player-kick deferred to Phase 10 per D-12) |

**Voice rules:**
- All UI text uppercase ONLY for the scene title and button labels (existing precedent: `WAITING ROOM`, `START GAME`, `CONNECT`).
- Body/label copy uses sentence case: `Players 3/6 — 3v3 on Open Field`, `Reduce players first (8 > 4 cap)`.
- Format tokens always rendered lowercase-v: `3v3` not `3V3` or `3 v 3`.
- Use em dash `—` (U+2014), not hyphen `-`, in the capacity header and browser row.
- Use bullet `•` (U+2022), not pipe or comma, in the browser row separator.

## Interaction Contract

| Element | Interaction | Visual feedback |
|---------|-------------|-----------------|
| Format `<select>` (host) | Native `change` event → `sendLobbySetConfig({ format })` | Browser-native focus ring; on submit, capacity header updates within one `lobby:updated` round-trip (typically <100ms LAN) |
| Format `<select>` (non-host) | not rendered — replaced by read-only `Format: <value>` label | n/a |
| Map preview card (host) | Pointer click on card → `sendLobbySetConfig({ mapId })` | Hover: card border lightens to `0x666666`. Selected: 2px gold `0xffdd55` border. Non-selected: 1px grey `0x444444` border |
| Map preview card (non-host) | not interactive — replaced by read-only `Map: <displayName>` label | n/a |
| Capacity header | static text, updates on every `lobby:updated` | live value swap; no animation |
| Lobby browser row | existing pointer click → join (unchanged) | existing hover `BTN_HOVER` (unchanged) |
| Reject error | server emits `lobby:error` with copy; client displays via `#statusText` (existing channel) for ~3s | text color `#ff4444`; auto-clears or replaced by next status update |

**Latency budget:** Config edits must visibly reflect within 200ms on LAN. The header line and selected-card border are the load-bearing affordances.

**Loading state:** none required — config edits are fire-and-forget; the client trusts the next `lobby:updated` broadcast to confirm. No spinner, no optimistic update.

## Layout Anchors (waiting room)

Existing scene uses absolute Phaser coordinates anchored to `cx = camera.centerX`, `cy = camera.centerY`. Phase 9 inserts a host-controls block between the existing subtitle (y=70) and the player list (y=120).

| Element | Y anchor | Notes |
|---------|----------|-------|
| `WAITING ROOM` title | 40 | existing |
| `Host: <name>` subtitle | 70 | existing |
| `Waiting for host to start...` hint | 88 | existing — REMOVE or move below capacity header (planner decides) |
| **Capacity header (new)** | 96 | centered at `cx` |
| **Format control (new)** | 116 | host: `<select>` at `cx + 30`; non-host: text at `cx + 30`; label at `cx - 150` |
| **Map picker block (new)** | 140 | host: 2 cards in a row centered at `cx`, card height 64 + 12px label gutter; non-host: single text line at `cx` |
| Player list start | 220 | shifted down from existing 120 to accommodate map block — planner confirms exact value |
| `START GAME` button | `cy + 120` | existing |

**Constraint:** Total waiting-room vertical extent must fit within a 720px-tall camera viewport. Player list rows are 36px each — 10 rows (max for 5v5) = 360px. Block math: 220 (top) + 360 (list) + 32 (xl) + 28 (button) = 640. OK.

## State Matrix

| State | Visible to | Visual treatment |
|-------|-----------|------------------|
| Host editing format | host only | `<select>` enabled, focus ring on interact |
| Host editing map | host only | preview cards interactive, hover/selected borders |
| Non-host viewing config | everyone except host | read-only text labels; no interactive affordance |
| Config update arriving | everyone | header line + read-only labels + lobby browser row all swap to new values atomically on `lobby:updated` |
| Capacity-downshift reject | host who attempted the change | `#statusText` shows `Reduce players first (N > M cap)` in `#ff4444` for 3s |
| Lobby in `LOADING/COUNTDOWN/ACTIVE` status | everyone | format/map controls hidden — out of scope for this phase but the scene already transitions away on `lobby:started` so no defensive UI needed |
| MAP_POOL has 1 entry | everyone | single map card renders non-interactive (selected border always on); no special copy |
