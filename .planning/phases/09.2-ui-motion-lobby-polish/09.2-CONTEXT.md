# Phase 9.2: UI Motion & Lobby Polish - Context

**Gathered:** 2026-05-21
**Status:** Ready for planning

<domain>
## Phase Boundary

The pre-match flow (splash → main menu → lobby → start → LOADING → countdown → gameplay) feels cinematic and music-driven, end-to-end. This phase **reshapes 9.2 beyond the original 3 ROADMAP success criteria** to absorb a full cinematic LOADING sequence (typewriter, map preview, joke/tip card, music-drop sync to game-start) and to merge prior UI-branch motion work without losing multiplayer phases 7–9.1.

**In scope:**
- Selective port of UI-branch assets into `multiplayer` branch (splash + main menu + music manager + scene-transition helper + audio + landscape video + new tilesets).
- "Click anything to..." gate screen (= UI's `SplashScene`).
- Cinematic main-menu intro synced to menu music drop (= UI's `MainMenuScene` cinematic, but converted to BitmapText).
- Lobby Start → LOADING transition (camera fade + music duck; per-client, no server protocol change).
- Cinematic LOADING content: typewriter map name → map preview fade-in → typewriter map info → joke/tip card from `content/loading-tips.txt`.
- Gameplay-music drop synced to COUNTDOWN-end via hardcoded offset constants.
- Two 96×64 pixel-art map thumbnails (downscaled from `world_background.png` / `dungeon_1_background.png`).
- Music volume profile: menu @ 0.05, lobby views @ 0.03 (ducked), gameplay @ TBD.

**Out of scope:**
- Re-opening completed Phase 7 (LOADING State + Match FSM) or Phase 8 (COUNTDOWN State). The Phase 8 zoom-in + 3-2-1-FIGHT! overlay already exists and is reused; this phase only **extends** LOADING content and adds music-sync, it does not rewrite COUNTDOWN.
- Rewriting `lobby-scene.ts`, `network-manager.ts`, or `loading-scene.ts` (multiplayer versions are canonical; UI-branch versions are rejected during conflict resolution).
- UI-branch's single-player-shaped `create-lobby-scene.ts` / `join-lobby-scene.ts` (multiplayer's LobbyScene Connect+Browser is the canonical entry path; menu items funnel into it).
- New protocol events for Start→LOADING sync (each client plays the transition locally).
- Beat-detection or programmatic music analysis (drop sync is hardcoded constants, tuned by ear).
- Account/Options/Credits scene functionality — they ship as navigable stubs only.
- Persistence of last-shown joke/tip across sessions.

</domain>

  - **DROP from UI scope (don't port):** `src/scenes/create-lobby-scene.ts`, `src/scenes/join-lobby-scene.ts` — incompatible with multiplayer's server-mesh flow; multiplayer's LobbyScene Connect+Browser is the canonical entry path.
  - **MERGE additively (combine both sides):** `src/scenes/scene-keys.ts` (union of all keys), `src/common/assets.ts` (add UI's keys without removing multiplayer's), `src/main.ts` (register all new scenes + keep multiplayer boot wiring), `src/scenes/preload-scene.ts` (UI's font/audio loads on top of multiplayer's), `public/assets/data/assets.json` (additive entries).
  - **CONVERT during port:** UI's main-menu and splash scenes use `Phaser.Text + setResolution(4)`. Phase 9.1-04 standardised the codebase on BitmapText via the Press_Start_2P atlas. Port the scenes but **rewrite text construction to use BitmapText** (FONT/FONT_TITLE/FONT_SMALL constants matching `lobby-scene.ts:18-21`).
- **D-03:** Boot flow after merge: `SplashScene → MainMenuScene → LobbyScene` (multiplayer). `src/main.ts` boots `SplashScene` instead of `LobbyScene` directly. UI's main-menu items `CRIAR LOBBY` and `ENTRAR EM LOBBY` both `startScene(this, SCENE_KEYS.LOBBY_SCENE)` — same destination; multiplayer LobbyScene already supports both flows (browse existing lobbies + create new from waiting room). `CONTA / OPCOES / CREDITOS` route to their respective stub scenes. `SAIR` stays as a no-op placeholder.

### Menu Intro & Click-Anything Gate
- **D-04:** SplashScene is the "click anything to..." gate (success criterion #1). Existing UI design: full-black background, blinking "PRESS ANYTHING TO GET HIGH IN THE FANTASY", any keyboard or pointer input → `fadeOut(400ms)` → `MainMenuScene`. SplashScene also calls `MusicManager.instance.loadTracks(this)` to preload menu+gameplay tracks. Convert text to BitmapText during port.
- **D-05:** MainMenuScene cinematic synced to menu-music drop at `MUSIC_DROP_MS = 2000ms`. Existing UI design: `fadeIn(400ms)` from black → `MusicManager.instance.playMenu(this)` → all UI hidden → at 2000ms title slams in (scale 1.3→1.0 over 250ms Back.Out + alpha 0→1 over 150ms) → subtitle fade-in @ 150ms delay → menu items staggered fade-in (60ms per item, start @ 200ms). Cinematic plays first-visit only (module-level `cinematicPlayed` flag). Accept as-is; convert text rendering to BitmapText.
- **D-06:** Menu background: keep UI's `landscape.mp4` video background (cover-fit, LINEAR filter on the video texture to avoid pixelArt nearest-neighbour smear; vignette overlay at 0x000000 @ 0.4 alpha for text legibility).

### Lobby Start → LOADING Transition
- **D-07:** Visual: camera fade-to-black + menu-music volume duck to 0 in parallel, over 400ms. Reuses UI's `scene-transition.ts` pattern but inverts into a "fade out then start" called from `lobby-scene.ts #onLobbyStarted` immediately before `scene.start(LOADING_SCENE)`. Eager DOM/configBlock destroy from Phase 9.1-03 stays — runs **before** the fade kicks off.
- **D-08:** Multi-client sync: each client plays the transition independently on receipt of `lobby:started`. **No new server protocol event, no server-side delay.** Existing LoadingScene min-display floor (Phase 7) absorbs the small per-client jitter (~50ms typical) so all clients hit COUNTDOWN within tolerance.
- **D-09:** During the 400ms transition the menu music is stopped (not crossfaded). Gameplay music starts when LoadingScene's cinematic enters its first beat (see D-13).

### Cinematic LOADING Content
- **D-10:** LoadingScene is extended (not rewritten) to host a ~8 second cinematic before handing off to GameScene/COUNTDOWN. Timing budget broken into tweakable constants at the top of the file:
  ```ts
  const T_MAP_NAME_MS    = 1500;  // typewriter map name
  const T_PREVIEW_FADE_MS = 1000;  // map preview fade-in
  const T_MAP_INFO_MS    = 2000;  // typewriter map info (mode, players, format)
  const T_GAP_MS         = 500;   // breathing room
  const T_TIP_CARD_MS    = 2500;  // joke/tip card display
  const T_FADE_OUT_MS    = 500;   // fade out to GameScene/COUNTDOWN
  // Total ~8000ms
  ```
  User must be able to tune these without hunting through the file body. **All cinematic timing lives in named constants at the top of `loading-scene.ts`.**
- **D-11:** Typewriter is a **bespoke helper**, not the netgfx package. Write `src/common/typewriter.ts` (~40 lines) that takes a BitmapText object + full string + chars-per-second rate + optional onComplete callback, uses `scene.time.addEvent` to reveal one character per tick. BitmapText-compatible (since `setText` works on BitmapText the same as Text). No npm dep, no third-party code to vet.
- **D-12:** Joke/tip source file: `content/loading-tips.txt`, one tip per line, lines starting with `#` are comments. File loaded once via `fetch('/content/loading-tips.txt')` from LoadingScene on first entry, parsed into a string array, cached in module scope, random pick per match. Empty / missing file falls back to a built-in fallback set of 3 lines so the cinematic never breaks. **You and your colleague populate this file in parallel** — no code changes required to add tips.

### Music Profile & Drop Sync
- **D-13:** Music profile:
  - SplashScene + MainMenuScene: menu music @ volume `0.05` (existing UI constant).
  - LobbyScene (Connect, Browser, Waiting Room): menu music ducks to volume `0.03`. Ducking happens on `LobbyScene.create()` via `MusicManager.instance.setMenuVolume(0.03)`. Add this method to MusicManager during port.
  - Lobby Start → LOADING transition: menu music stops (during the 400ms fade-to-black).
  - LoadingScene cinematic onwards (LOADING + COUNTDOWN + GameScene): gameplay music. Gameplay music **starts at a precomputed offset before LOADING ends** so that the drop hits the moment COUNTDOWN ends and gameplay begins.
- **D-14:** Drop sync via hardcoded constants, tuned by ear. Add `GAMEPLAY_MUSIC_DROP_MS` to `music-manager.ts` (offset from track start to the climax). Compute `gameplay_music_start_delay = (LOADING_total + COUNTDOWN_total) - GAMEPLAY_MUSIC_DROP_MS`. Start the gameplay track inside LoadingScene at that computed moment. **No server-driven music sync, no beat detection.** Tune constants by ear; document the math in a comment above the constants.

### Map Thumbnails (Success Criterion #3)
- **D-15:** Two 96×64 PNGs produced by ImageMagick downscale of the existing map backgrounds (which arrive via the UI-branch port):
  ```
  magick public/assets/images/levels/world/world_background.png \
    -resize 96x64^ -gravity center -extent 96x64 -filter Point \
    public/assets/images/levels/world/thumbnail.png

  magick public/assets/images/levels/dungeon_1/dungeon_1_background.png \
    -resize 96x64^ -gravity center -extent 96x64 -filter Point \
    public/assets/images/levels/dungeon_1/thumbnail.png
  ```
  Replaces the placeholder green-"W" / purple-"D" files. No code change — `assets.json` + `ASSET_KEYS.MAP_THUMB_*` + explicit PreloadScene loads (Phase 9.1-01) already wired. Constraints from the source todo locked: no AA, no border, no baked text, exactly 96×64.
