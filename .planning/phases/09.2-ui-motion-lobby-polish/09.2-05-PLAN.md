   If either is missing, halt and notify — Plan 01 Task 1 must have completed first.

2) Confirm `magick` (ImageMagick v7) is installed and on PATH:
   ```
   magick -version
   ```
   Expected output: `Version: ImageMagick 7.x.x ...`. If `magick` not found, install from https://imagemagick.org/ on Windows (default install adds to PATH), or use `convert` (v6 fallback — substitute the command name in step 3).

3) Run the two downscales from repo root (verbatim per CONTEXT.md D-15):
   ```
   magick public/assets/images/levels/world/world_background.png ^
     -resize 96x64^^ -gravity center -extent 96x64 -filter Point ^
     public/assets/images/levels/world/thumbnail.png

   magick public/assets/images/levels/dungeon_1/dungeon_1_background.png ^
     -resize 96x64^^ -gravity center -extent 96x64 -filter Point ^
     public/assets/images/levels/dungeon_1/thumbnail.png
   ```
   (PowerShell uses `^` for line continuation; bash/cmd users substitute `\` or single-line.)

   Notes:
   - `-resize 96x64^` (the `^` means "fill the box, allow overflow") combined with `-gravity center -extent 96x64` crops the center to exactly 96×64.
   - `-filter Point` enforces nearest-neighbor (no AA, preserves hard pixel edges).
   - The two `^^` in the Windows PowerShell version are intentional: outer `^` is PowerShell line-continuation, inner `^` is the ImageMagick "fill" flag.

4) Confirm output:
   ```
   magick identify public/assets/images/levels/world/thumbnail.png
   magick identify public/assets/images/levels/dungeon_1/thumbnail.png
   ```
   Both must report `... PNG 96x64 96x64+0+0 ...` (the `96x64` is the canvas size; if it reports differently, the resize+extent didn't pin to 96×64).

5) Do NOT touch any code. Do NOT modify `assets.json`, `ASSET_KEYS`, or the PreloadScene/LobbyScene `preload()` calls — those are correctly wired from Phase 9.1-01.
  </action>
