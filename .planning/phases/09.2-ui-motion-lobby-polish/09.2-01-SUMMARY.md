# Phase 09.2 Plan 01: UI-branch port + boot-flow change Summary

Port UI-branch's cinematic main-menu surface (Splash → MainMenu → Account/Options/Credits stubs) onto the multiplayer branch with BitmapText conversion, MusicManager extensions, and a new SplashScene boot entrypoint — foundation for Plans 02–05.

## Key Decisions

- **D-02 CONVERT enforcement.** Every text element in every ported scene uses BitmapText (Press_Start_2P atlas, 8/16/32 px sizes per UI-SPEC §Typography). Verified by grep: zero `setResolution(`, zero `this.add.text(`, zero `new Phaser.GameObjects.Text` across splash-scene.ts, main-menu-scene.ts, menu-placeholder.ts, account-scene.ts, options-scene.ts, credits-scene.ts.
- **D-03 boot flow + lobby routing.** `main.ts` boots `SPLASH_SCENE`. Both menu items `CRIAR LOBBY` and `ENTRAR EM LOBBY` `startScene(this, SCENE_KEYS.LOBBY_SCENE, 300)` — multiplayer's LobbyScene Connect+Browser is the canonical entry, so dropping `CREATE_LOBBY_SCENE` and `JOIN_LOBBY_SCENE` per D-02 has zero functional cost.
- **D-13 / WARNING 5 symmetric volume profile.** `MainMenuScene.create()` calls `MusicManager.instance.setMenuVolume(0.05)` on every entry. Idempotent (no-op until menu music is initialised, which `playMenu()` does in the same `create()`). Future-proofs Plan 03's lobby duck (0.03) so back-nav restores 0.05 without new wiring.
- **D-14 drop-sync constant exported.** `export const GAMEPLAY_MUSIC_DROP_MS = 4000` lives in music-manager.ts; Plan 04 will compute `delay = LOADING_TOTAL + COUNTDOWN_TOTAL - GAMEPLAY_MUSIC_DROP_MS` against this value.
- **BitmapFont bootstrap.** SplashScene and MainMenuScene self-load `press_start_2p` (cache-guarded) because they run before `PreloadScene`. PreloadScene also self-loads it (additively) so direct-jump debug routes still work. Three idempotent load sites in total; first wins, subsequent are no-ops.
