# Phase 09.2 Plan 04: LoadingScene Cinematic + Music-Drop Sync Summary

Replace the Phase 7 placeholder LoadingScene UI (LOADING MATCH label + player rectangle) with an 8-second cinematic — map name typewriter, map preview fade-in, mode/player info typewriter, tip card — and start gameplay music with a computed delay so its drop lands at COUNTDOWN-end. Phase 7's match:loaded sync barrier is preserved verbatim.

## Key Decisions

- **D-10 timing constants hoisted.** All six cinematic beats live as `const T_*_MS` at the top of loading-scene.ts; total `T_CINEMATIC_TOTAL_MS` derived once. Future tuning requires editing only the constant block.
- **D-11 dep-free typewriter.** `src/common/typewriter.ts` (~40 lines) uses `scene.time.addEvent({ delay, repeat: total - 1 })` for one-character-per-tick linear reveal. No netgfx, no npm dep. BitmapText-compatible because `setText` works identically on Text and BitmapText.
- **D-12 module-cached tip fetch.** `loadTips()` fetches `/content/loading-tips.txt` once per page load (cached at module scope), strips `#` comments and blank lines, picks a random non-comment line per match. Empty/missing file falls back to 3 built-in lines silently — no user-visible error.
- **D-14 music-drop math.** `delay = T_CINEMATIC_TOTAL_MS + COUNTDOWN_TOTAL_MS - GAMEPLAY_MUSIC_DROP_MS = 8000 + 3500 - 4000 = 7500ms` from `LoadingScene.create()`. `MusicManager.playGameplay(this)` handles the autoplay-unlock retry internally (already triggered by SplashScene gesture).
- **Phase 7 barrier preserved + extended.** `#sendLoadedAck`, `#onMatchStateChanged`, `#scheduleTransition` keep their exact Phase 7 semantics. The cinematic's `T_CINEMATIC_TOTAL_MS` is also factored into `#scheduleTransition`'s wait calculation, so even when the server emits COUNTDOWN within a frame of `match:loaded` (local-stub case) the user still sees the full 8s cinematic.
- **BLOCKER 1 fix (carried from plan-checker).** Map info typewriter renders 2 lines (MODE / PLAYERS) instead of 3. The plan's earlier FORMAT row mapped to a non-existent `LobbyConfig.format` enum id — MODE already conveys "2v2" via MatchConfig.mode. T_MAP_INFO_MS stays at 2000ms (perLine = 1000ms — slightly slower, more readable cadence).
