# Phase 09.1 Plan 01: Thumbnail Preload Fix Summary

One-liner: Explicit `this.load.image()` calls in `PreloadScene.preload()` for `MAP_THUMB_WORLD` and `MAP_THUMB_DUNGEON_1` so both textures reach the cache before `LobbyScene` renders — closes UAT gap where host map cards rendered the blue `0x223366` fallback rectangle instead of the placeholder PNGs.

## What Changed

**`src/scenes/preload-scene.ts`** — added 14 lines inside `preload()` immediately after the existing `this.load.pack(...)` call (lines 18-32):

```ts
this.load.image(
  ASSET_KEYS.MAP_THUMB_WORLD,
  'assets/images/levels/world/thumbnail.png',
);
this.load.image(
  ASSET_KEYS.MAP_THUMB_DUNGEON_1,
  'assets/images/levels/dungeon_1/thumbnail.png',
);
```

A multi-line comment block was added explaining why the explicit load is needed (the `pack(MAIN, ...)` loader only resolves entries whose key matches `MAIN`, so the nested `levels/world` / `levels/dungeon_1` sub-pack entries never reached the texture cache).
