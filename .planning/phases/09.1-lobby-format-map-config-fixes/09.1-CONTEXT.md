# Phase 9.1 — Lobby Config Polish (Gap Closure)

One-page summary of the gap-closure scope produced by `/gsd-plan-phase --gaps` against Phase 9's UAT failures. Decimal phase (not a new feature surface) — all work targets falsifiable gaps from `09-UAT.md`.

## Source of Truth

`.planning/phases/09-lobby-format-map-configuration/09-UAT.md` (status: complete) — 9 tests, 5 pass, 4 issues. The 4 issues produced 5 falsifiable gap entries (Test 1 split into sub-gaps 1a + 1b; Tests 4 and 8 fold into the thumbnail-load gap; an out-of-band cosmetic alignment gap was logged during Test 4 review; Test 9 produced the host black-screen gap).

## Gaps Addressed (5 → 4 plans)

| Gap (UAT) | Severity | Plan | Hypothesis (from UAT) |
|---|---|---|---|
| Thumbnails do not render (Tests 4 & 8) | major | **9.1-01** | `this.load.pack(MAIN, ...)` does not actually load entries inside the `levels/world` and `levels/dungeon_1` packs at preload time. Explicit `this.load.image(MAP_THUMB_*)` in PreloadScene.preload() fixes it. |
| Player list overlaps map control area (Test 1b) | major | **9.1-02** | Map cards at y=180 have bottom edge at y=212; player list at y=220 leaves only 8px clearance. Card labels (text under cards) push into the player list. Player list base Y must move down (or cards must move up). |
| Format label vs `<select>` not vertically aligned (Test 4 out-of-band) | cosmetic | **9.1-02** | DOMElement `<select>` (~22px native height) and Phaser.Text use different vertical metrics. Fix by aligning origins / nudging y. |
| Host->loading->game has ~1s black-screen pause (Test 9) | major | **9.1-03** | Phaser DOMElement `#formatSelectDom` and `#configBlockObjects` are torn down only on SHUTDOWN, which fires AFTER `scene.start(LoadingScene)`. The browser composites the DOM `<select>` against the new scene for one frame -> visual stall. Fix: explicit cleanup BEFORE `scene.start()` in `#onLobbyStarted`. |
| Lobby text appears blurry (Test 1a) | cosmetic | **9.1-04** | `pixelArt: true` is already set in `src/main.ts`. Phaser Text rasterizes via canvas2d at base DPI then gets nearest-neighbor up-scaled -> blocky blur. Fix: call `setResolution(window.devicePixelRatio || 2)` on the lobby's text objects (or switch to BitmapText, but resolution bump is cheaper). |

## Plans

- **9.1-01 — Thumbnail preload fix** — explicit `this.load.image()` for MAP_THUMB_WORLD and MAP_THUMB_DUNGEON_1 in `PreloadScene.preload()` (LBC-04 thumbnail visibility).
- **9.1-02 — Lobby layout polish** — combine layout fix (gap 1b: player list Y push) with cosmetic alignment (Format label↔select). Same file (`src/scenes/lobby-scene.ts`), same render pass, atomic visual change.
- **9.1-03 — Host scene-transition cleanup** — explicit DOM destroy + configBlock destroy in `#onLobbyStarted` before `scene.start(LoadingScene)`. Pre-empts SHUTDOWN-timing race.
- **9.1-04 — Pixel-art text crispness** — bump text resolution on lobby text objects (and verify no global config change needed since `pixelArt: true` is already set).

## Out of Scope

- Replacing the placeholder solid-color thumbnails with real pixel art — already tracked in `.planning/todos/pending/2026-05-21-replace-map-thumbnail-placeholders.md`. Phase 9.1 only fixes the load path; once loaded, the existing placeholder PNGs satisfy the UAT gap (`Both thumbnails are visible`).
- Test 5 (non-host read-only labels) — was `pending` in UAT, never executed. Not a gap until verified failing.
- Any new feature surface. This is polish-only.
