# Phase 09.3 Plan 04: Input Rebinds + Dash Summary

Shipped the input-layer changes for Phase 9.3: rebound the radial-menu spell-cycle from
CTRL to SPACE (D-17/18/19 — frees Ctrl+W from closing the browser tab), added a Shift
dash with WASD-vector direction and last-faced fallback (D-13/14/15/16), and extended
RUNTIME_CONFIG with the seven dash tunables + i-frame support per the tunable-first
philosophy. Pure input + player-movement feature; no new network protocol — dash position
rides the existing 20 Hz pos-mirror channel (D-15).

## What Was Built

### Key rebind (`src/components/input/keyboard-component.ts`)

- Removed `#ctrlKey` field and its `KeyCodes.CTRL` binding (D-19: CTRL fully unbound).
- Added `#spaceKey` (replaces CTRL for radial menu) and `#shiftKey` (new dash binding).
- `isRadialMenuKeyJustDown` now returns `JustDown(this.#spaceKey)` — transparent rename
  for all existing call sites (e.g. `game-scene.ts:185` `#handleRadialMenuInput`).
- New getter `isDashKeyJustDown` returns `JustDown(this.#shiftKey)`.
- Added `keyboardPlugin.addCapture('SPACE,SHIFT')` to prevent Chrome's default
  page-scroll on SPACE and any browser interference on SHIFT while the game has
  focus. CTRL is intentionally NOT in the capture list so Ctrl+W/T/R remain
  browser shortcuts (D-19).
- Updated the header comment block to reflect the new bindings.

### Base input class (`src/components/input/input-component.ts`)

Mirrors the radial-menu key pattern:
- `#dashKey: boolean` field initialized to false in constructor.
- `isDashKeyJustDown` getter + setter.
- `reset()` clears `#dashKey` to false.

### Dash tunables (`src/common/config.ts` + `src/common/runtime-config.ts`)

Seven new exports, all importable + mirrored into `RUNTIME_CONFIG`:

| Constant | Default | Purpose |
|----------|---------|---------|
| `DASH_COOLDOWN_MS` | 1500 | ms between dashes |
| `DASH_DISTANCE_TILES` | 3 | dash distance in tiles (96 px) |
| `DASH_DURATION_MS` | 150 | dash motion duration → 640 px/s |
| `DASH_IFRAMES_ENABLED` | false | i-frames during dash |
| `DASH_IFRAMES_MS` | 150 | i-frame window when enabled |
| `DASH_CANCELS_CAST` | true | Shift mid-cast aborts cast |
| `DASH_INTERRUPTABLE_BY_CAST` | false | 1/2/3 mid-dash is ignored |

These coexist cleanly with Plan 02's damage-pipeline constants
(`RESPAWN_DELAY_MS`, `PLAUSIBILITY_RANGE_PX`, `PLAUSIBILITY_STALE_MS`, `MAX_SPELL_DAMAGE`).

### Player.dash() (`src/game-objects/player/player.ts`)

- Public state added: `iFrameUntil: number = 0`, `isDashing: boolean = false`.
- Private state: `#lastDashTime: number = -Infinity`.
- `dash()` flow:
  1. Cooldown gate: `if (now - #lastDashTime < DASH_COOLDOWN_MS) return;`
  2. Direction = WASD vector (`controls.isLeft/Right/Up/DownDown` summed).
  3. Fallback when no WASD held: read `this.direction` (UP/DOWN/LEFT/RIGHT enum)
     and set dx/dy accordingly.
  4. Cast-cancel: if `DASH_CANCELS_CAST` and `stateMachine.currentStateName === CASTING_STATE`,
     `setState(IDLE_STATE)` before applying velocity.
  5. Speed: `DASH_DISTANCE_TILES * 32 / (DASH_DURATION_MS / 1000)`. With defaults: 640 px/s.
  6. `body.setVelocity((dx/len)*speed, (dy/len)*speed)`.
  7. Set `isDashing = true`, `controls.isMovementLocked = true`, `#lastDashTime = now`.
  8. If `DASH_IFRAMES_ENABLED`, set `iFrameUntil = now + DASH_IFRAMES_MS`.
  9. `scene.time.delayedCall(DASH_DURATION_MS, () => { body.setVelocity(0,0); isDashing=false; controls.isMovementLocked=false; })`
     with a `this.active && this.body` guard against mid-dash teardown.

The `isMovementLocked = true` setting is critical (RESEARCH.md §3 landmine 1):
`MoveState` reads WASD every frame and re-writes velocity, which would otherwise
overwrite the dash velocity instantly. The same gate `FireBreath` and `FireBreathChanneling`
use is reused.

### Cast-during-dash guard (`src/components/game-object/spell-casting-component.ts`)

Added at the top of `canCast()`:
```ts
if (
  !RUNTIME_CONFIG.DASH_INTERRUPTABLE_BY_CAST &&
  (this.gameObject as unknown as { isDashing?: boolean }).isDashing === true
) {
  return false;
}
```

The duck-typed cast avoids importing the concrete `Player` class into a generic
component (would create a cycle and tie the component to the player). Non-Player
GameObjects don't have `isDashing` defined — the optional read is falsy and the
guard is a no-op for them.

### GameScene wiring (`src/scenes/game-scene.ts`)

- New `#handleDashInput()` method called once per frame from `update()`:
  ```ts
  if (this.#combatLocked) return;
  if (this.#deathLockActive) return;
  if (!this.#controls.isDashKeyJustDown) return;
  if (!this.#player?.active) return;
  this.#player.dash();
  ```
- Pre-declared `#deathLockActive: boolean = false` as a class field next to
  `#combatLocked` so Plan 03 can flip it without redeclaring (see Coordination
  Notes below).

### Debug-panel type widening (`src/debug/debug-panel.ts`)

Relaxed `Record<string, number>` → `Record<string, number | boolean>` in two
spots (`#defaultValues` field, two casts in `#buildRow` slider input handler and
`#resetAll`). The panel only renders sliders for the explicit `SECTIONS` list, so
no boolean tunables become user-editable sliders — this widening is purely a
type-system relaxation needed because `RUNTIME_CONFIG` now includes three booleans.
Tracked as **[Rule 1 - Bug]** because adding the booleans introduced a typecheck
error the same task created.

  excluded so Ctrl+W/T/R remain browser shortcuts (D-19).
