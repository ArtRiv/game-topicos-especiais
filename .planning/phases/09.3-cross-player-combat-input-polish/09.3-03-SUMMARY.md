# Phase 09.3 Plan 03: Cross-Player Damage Wiring + Elimination/Respawn Summary

Shipped the **client-side** half of the host-authoritative damage pipeline that Plan 02
built on the server. Caster's local-overlap detection emits `spell:hit`; the server
validates and broadcasts `damage:confirmed`; both clients apply `LifeComponent.takeDamage`
(i-frame guarded per Plan 04 contract); and on HP=0 the server broadcasts `elimination`
followed by `respawn` after `RESPAWN_DELAY_MS`. The killed player sees a full-screen
dark overlay + centered BitmapText "RESPAWNING IN N..." countdown; observers see the
killed player tinted gray. Closes PVP-02 (cross-player damage detection) and PVP-05
(damage only on server confirmation) at the code level; final closure pending the
two-client UAT playtest (Task 4 checkpoint).

## What Was Built

### LifeComponent (src/components/game-object/life-component.ts)

- `heal(amount: number): void` — caps at maxLife.
- `resetToFull(): void` — bypasses the `currentLife === 0` early-return on `takeDamage`,
  used by respawn (D-08) to revive from 0 HP.

### CharacterGameObject (src/game-objects/common/character-game-object.ts)

- Public `lifeComponent` getter so `#onDamageConfirmed` can apply damage uniformly to
  local AND remote Player instances.

### SpellCastPayload — both type files (src/networking/types.ts, game-server/src/types.ts)

- New `spellType: string` field carries the SPELL_ID class constant (e.g. `FIRE_BOLT`).
- The existing `spellId: string` field now carries the per-cast UUID, so the host
  validator + cross-client dedupe + NETWORK_SPELL_DESTROYED can correlate spells stably.
- Critical for #onRemoteSpellCast: it now looks up the factory by `payload.spellType`
  (not `payload.spellId`, which is no longer a SPELL_ID).

### SpellCastingComponent (src/components/game-object/spell-casting-component.ts)

At cast time, before EVENT_BUS.emit:

- Generates `spellInstanceId = Phaser.Math.RND.uuid()`.
- Attaches three data attributes on `spell.gameObject` via setData:
  - `spellId` ← the UUID (cross-client correlation key)
  - `casterId` ← NetworkManager.localPlayerId (try/catch tolerant for offline play)
  - `spellType` ← the SPELL_ID constant (survives bundle minification, unlike `constructor.name`)
- Emits `SPELL_CAST` with both `spellInstanceId` (NEW) and `spellId` (legacy — preserved).

### GameScene (src/scenes/game-scene.ts)

New fields:
- `#remotePlayerGroup: Phaser.GameObjects.Group` — cross-player overlap target.
- `#appliedDamageSpellIds: Set<string>` — NETWORK_DAMAGE_CONFIRMED dedupe.
- `#deathOverlay`, `#deathCountdownText`, `#deathCountdownTimer`, `#deathCountdownRemaining`
  — local-player elimination UI state.

Setup:
- `#remotePlayerGroup` instantiated alongside `#remoteSpellGroup` in `create()`.
- `#setupPlayer` tags local player via `setData('playerId', localId)`.
- `#onRemotePlayerUpdate` (lazy-spawn branch) tags remote + adds to `#remotePlayerGroup`.

Cross-player overlaps in `#registerColliders`:
- **A:** `this.physics.add.overlap(this.#player, this.#remoteSpellGroup, …)` — local player
  hit by remote spell. Reads `spell.getData('spellId'|'casterId'|'spellType')`, FF pre-checks,
  emits `nm.sendSpellHit({...})`, calls `spell.explode?.()` for visual.
- **B:** `this.physics.add.overlap(this.#player.spellCastingComponent.spellGroup, this.#remotePlayerGroup, …)`
  — local spell hits remote player. Mirror of A.

Damage application:
- `#onDamageConfirmed`: dedupe check → i-frame guard for local target
  (`if (this.time.now < this.#player.iFrameUntil) return;`) → `lifeComponent.takeDamage(payload.amount)`
  on local OR matching remote.

D-04 wall-desync close:
- `#onSpellDestroyed`: scans both `#remoteSpellGroup` AND local `spellGroup`, matches by
  `getData('spellId')`, calls `.explode()` or `.destroy()`.
- Local FireBolt/EarthBolt × earth-wall overlap broadcasts `nm.sendSpellHitEnvironment({...})`.

Elimination + respawn (D-08..D-11):
- `#onElimination` → if local: `#applyLocalDeath()` (dark overlay 0x222233@55% alpha at depth 9999,
  centered 32px BitmapText with `press_start_2p` font at depth 10000, 1000ms loop timer,
  gray tint 0x666666, velocity zero, `controls.isMovementLocked=true`, `#deathLockActive=true`).
  Remote: gray tint only.
- `#onRespawn` → if local: `#clearLocalDeath()` + `setPosition(payload.x,y)` + `lifeComponent.resetToFull()`
  + `clearTint()`. Remote: same minus the overlay teardown.

Input gating:
- Added `if (this.#deathLockActive) return;` to `#handleRadialMenuInput`, `#updateFireBreathChanneling`,
  `#updateEarthWallSpell`. (`#handleDashInput` already had it from Plan 04.)

SHUTDOWN cleanup:
- Unsubscribes the 4 new EVENT_BUS handlers.
- Calls `#clearLocalDeath()` (idempotent — safe whether or not the player was dead).
- Clears `#appliedDamageSpellIds`.

### event-bus.ts

Documentary `SpellCastEventPayload` type alias added near `CUSTOM_EVENTS`. Phaser
EventEmitter is structurally `...args:any[]`, so this is not enforced — but it
makes the SPELL_CAST shape self-documenting and prevents shape drift on future edits.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] SpellCastPayload had no spellType field; replacing spellId with UUID would break factory lookup**
- **Found during:** Task 1 design (before any code changes landed).
- **Issue:** Plan instructed adding `spellId` (already existed) and threading the per-cast
  UUID through `SpellCastPayload.spellId`. The existing `#onRemoteSpellCast` looks up the
  factory via `SPELL_FACTORY_REGISTRY[payload.spellId]` — replacing the SPELL_ID constant
  with a UUID would crash every remote spell because `SPELL_FACTORY_REGISTRY[uuid]` is undefined.
- **Fix:** Added a NEW `spellType: string` field to `SpellCastPayload` on both client + server
  type files. `spellId` now carries the UUID; `spellType` carries the SPELL_ID constant.
  Updated `#onLocalSpellCast` to populate both; `#onRemoteSpellCast` looks up the factory
  by `spellType` with a fallback to `spellId` for older peers.
- **Files modified:** `src/networking/types.ts`, `game-server/src/types.ts`, `src/scenes/game-scene.ts`
- **Commit:** 52d58a3

**2. [Rule 2 - Missing critical functionality] CharacterGameObject had no public lifeComponent getter**
- **Found during:** Task 2 (writing `#onDamageConfirmed`).
- **Issue:** `_lifeComponent` is `protected` on CharacterGameObject; `#onDamageConfirmed`
  needs to call `lifeComponent.takeDamage` on BOTH local and remote Player instances. The
  cleanest fix is a public getter (other components like `controls`, `stateMachine`,
  `animationComponent` already follow this pattern).
- **Fix:** Added `get lifeComponent(): LifeComponent { return this._lifeComponent; }` to
  CharacterGameObject. Mirrors the existing accessor pattern.
- **Files modified:** `src/game-objects/common/character-game-object.ts`
- **Commit:** cadb84a

### Plan-text deviations (worth flagging, not auto-fixes)

- **`spell.constructor.name` avoided.** RESEARCH.md §1 landmine 2 warned that production
  minification can mangle constructor names. Used `spell.getData('spellType')` instead,
  set at cast time from the SPELL_ID constant (immune to minification). Kept
  `spell.constructor.name` as a fallback for spell objects that somehow lack the data

- **SHUTDOWN handler was already in place.** Plan said "add one if missing" — it was already

- **No `#onElimination`/`#onRespawn` stub commit** — used compile-time stubs inside Task 2
  to land that commit cleanly, then filled them in within Task 3 (atomic per-task commits
  preserved; no broken intermediate state).

## Threat Model Compliance

Mitigations from plan's `<threat_model>` that landed in code:

- **T-09.3.03-01 (Spell missing spellId/casterId data attributes):** Both overlap callbacks
  early-return when `getData('spellId')` or `getData('casterId')`/`getData('playerId')`
  return undefined. No log spam on the rapid-overlap path.
- **T-09.3.03-02 (Duplicate NETWORK_DAMAGE_CONFIRMED applied twice):** `#appliedDamageSpellIds`
  Set dedupes per spellId; cleared on SHUTDOWN.
- **T-09.3.03-05 (DoS via massive overlap):** Each overlap emits a single sendSpellHit per
  pair per frame; server-side dedupe (Plan 02 `tryConsumeHit`) caps the validated broadcasts.

Accepted residual risks per threat model:
- T-09.3.03-03 (peer-spoofed EliminationPayload): server is the only emitter; client trusts
  socket.io source — no peer-to-peer auth boundary at this layer.
- T-09.3.03-04 (death overlay reveals state to observers): required for gameplay.
