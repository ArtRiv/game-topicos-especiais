# Phase 09.3 Plan 01: Phantom Fireball + Earth-Wall Symmetry + State-Machine Queue Fix Summary

Closed D-20 (phantom right-flying fireball), D-21 (earth wall blocked fireball for caster only), and latent E10 (queued state-transition args double-wrapped) — three independent multiplayer combat defects fixed in a single change-set; no net-protocol changes; ships independently of Plans 02/03/04.

## What Changed

### Task 1 — Phantom-fireball strict-drop guard + self-filter
**File:** `src/scenes/game-scene.ts` (`#onRemoteSpellCast`, was lines 1747-1770)

- Removed the straight-right defensive fallback `payload.targetX ?? payload.x + 1, payload.targetY ?? payload.y` (was lines 1760-1761).
- Added self-filter (new line 1761): `if (nm && payload.playerId === nm.localPlayerId) return;` — mirrors `#onRemotePlayerUpdate` line 1642.
- Added strict null-guard (new line 1767): `if (payload.targetX == null || payload.targetY == null) { console.warn(...); return; }`.
- Factory call (now lines 1772-1779) uses `payload.targetX, payload.targetY` directly — no fallback.

Commit: `68f37f2`

## Decisions Made

1. **`==` over `===` for null-guard** (intentional): Catches both `null` (JSON-preserved) and `undefined` (JSON-absent) per debug doc E8. Lint typically discourages `==` but here it is the correct contract semantics — kept anyway since lint did not error.
2. **console.warn over throw**: A single malformed message must not crash the scene; `console.warn` surfaces producer-side bugs without taking down the active match.
3. **Pillar damage stays client-local for v1**: Each observer's overlap runs on their own physics so each client decrements pillar HP independently. Acceptable today because pillar HP is client-local visual state; if desync becomes visible, route through host validator (Plan 02 pattern). Documented inline.
